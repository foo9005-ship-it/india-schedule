# 北山文化圏センター 打合せ議事録 自動生成用システムプロンプト（v3）

2026-09-15、Claude（Cowork）が実際に手作業で議事録を1件作成した際に確立された
執筆ルールを反映した版。v2からの変更点は以下。

## v2からの変更点

- 「です・ます調」を明示的に禁止し、体言止め・箇条書きを徹底
- 発言者を区別する必要がある場合の記法「【発言者名】」を追加
- 宿題（ToDo）を各セクション内に埋め込む方式から、末尾の
  「決定・確認事項（アクションアイテム）」セクションにまとめる方式に変更
- 発言者名について、ユーザーからの話者マッピング指示（Zoom表示名≠実際の発言者、
  という状況が実際に発生したため）を優先する旨を明記
- 出席者の所属が不明な場合は空欄にする旨を明記

## 話者マッピングについて（重要）

Zoomの発言者ラベルは「Zoomにログインしているアカウント名」であり、実際の発言者と
異なる場合がある（画面共有・回線都合で別の人がホストのアカウントのまま話す等）。
文字起こしだけからは機械的に判定できないため、依頼者（末吉氏）から
「Zoom表示名→実際の発言者名」の対応が明示された場合はそれに従うこと。
指示がなければ、Zoomの表示名をそのまま使用し、推測で人物を補正しない。

## system プロンプト本体

`system_prompt_v3.txt` を参照。

## 運用フロー（トリガー: 末吉氏による手動起動）

1. 末吉氏が、Zoom文字起こし（VTT等）・（あれば）補足メモ・出席者情報・
   （必要なら）話者マッピング指示をClaude Codeセッションに渡す
2. Claude（本システムプロンプトに従い）が議事録本文JSONを生成
3. `src/drive_sync.py : get_latest_base()` で直近の打合せ記録簿を取得
4. `src/generate_minutes.py : generate()` でテンプレートに流し込み
5. `src/drive_sync.py : upload_result()` でGoogle Driveの
   「議事録_自動生成」フォルダへアップロード（同日重複時はファイル名に連番を付与）

対話型セッション単体でのDriveアップロードは、バイナリをBase64で
モデル自身が転記する必要がありコスト・信頼性の両面で非現実的なため、
必ずコード実行（Claude CodeのBashツール等）でdrive_sync.pyを実行する形にすること。
